# Хронология решений — реализация `lecture-transcript-pipeline`

Ведётся автономно во время выполнения `/opsx:apply`. Читать сверху вниз.

---

## 0. Стартовые условия (обнаружено)

| Что | Факт |
|---|---|
| Репозиторий | пустой, только `openspec/` и `.claude/`. Код с нуля |
| Платформа исполнения | **macOS (darwin, arm64)**, а не WSL2+Docker из design |
| GPU | **нет CUDA**, `nvidia-smi` отсутствует |
| ffmpeg | 8.1.1 есть, `videotoolbox`/CPU; nvdec недоступен |
| docker | 29.4.0 есть, но без NVIDIA runtime |
| Эталонная запись | **найдена**: `~/Downloads/wr_20260909_1150.mp4` |
| Python | 3.13.4 (pyenv), `uv` есть |

### Решение 0.1 — что делать с расхождением платформы

Целевая платформа по design — WSL2+Docker+RTX 4060. Разработка идёт на macOS.
Принято: **писать переносимый код, GPU-специфику держать за конфигом с CPU-фолбэком.**

- `hwaccel` — параметр, а не хардкод (`cuda` / `videotoolbox` / `none`);
  на macOS проверяем CPU-путь, на целевой машине включается `cuda`.
- Задачи, где проверка требует физически RTX 4060 (1.1, 1.2 частично, 7.2, 7.4)
  или скачивания многогигабайтных весов, **не отмечаются как выполненные** —
  артефакт создаётся, проверка помечается как невыполнимая здесь. См. раздел «Не проверено».

### Решение 0.2 — контракты пишутся в главной сессии, реализация — параллельно

Чтобы параллельные сабагенты не разъехались по типам, весь обмен данными между
стадиями зафиксирован заранее в `src/lecture_transcript/contracts.py`
(dataclasses + `Protocol` для `OcrBackend` / `AsrBackend`). Сабагентам запрещено
его править — только докладывать о необходимости изменения.

Границы владения: каждый сабагент пишет только в свой пакет
`src/lecture_transcript/<capability>/` и свои файлы тестов. `pyproject.toml`
и `contracts.py` — за главной сессией.

### Решение 0.3 — git

`git init` выполнен (репозитория не было) — чтобы аудит мог смотреть диффы.
Коммиты не делаются без явной просьбы.

### Решение 0.4 — маркеры pytest вместо пропуска проверок

Введены маркеры `reference` (нужна эталонная запись), `gpu`, `models`, `slow`.
Тесты, требующие тяжёлых ресурсов, пишутся, но не гоняются в общем прогоне.
Это позволяет проверить их на целевой машине, не размывая критерий готовности.

Волна 2: `slide-extraction` (3.1–3.7) — ждёт агента fixtures, потому что все

Волна 3: сквозная проверка 7.1–7.6 — после всех остальных.

### Решение 1.1 — почему связь между стадиями только через `contracts.py`

Пакеты стадий не импортируют друг друга. Это позволило запустить 7 агентов
параллельно без конфликтов: каждый видит только свои требования и общий тип.
Оркестрация (порядок D2, выгрузка моделей D7) — целиком в `cli.py`, стадии
о ней не знают.

### Решение 1.2 — тяжёлые модели здесь не ставятся

PaddleOCR, pix2tex, Qwen2.5-VL, GigaAM-v2, Whisper large-v3, silero-vad —
гигабайты весов и GPU-колёса, на macOS без CUDA бесполезны. Всем агентам задано:
ленивый импорт внутри `check_availability()`, честный `Availability(False, reason)`
без установленной библиотеки, а вся логика вокруг моделей (реестры, роутинг,
сборка, глоссарий, выравнивание пунктуации, деградация без глоссария) — в чистых
функциях, покрытых тестами на фейковых бэкендах. Тесты на реальных весах написаны
и помечены маркером `models` — запускаются на целевой машине.

Обоснование: иначе половина спеки осталась бы непокрытой вообще, а так проверено
всё, кроме собственно качества распознавания.

## 2. Волна 1 — отчёты

### 2.1 core (1.3, 1.4) — готово, 40 тестов зелёные

Реализованы `cli.py` (argparse, оркестрация цепочки D2, `unload()` между стадиями),
`config.py` + `default_config.yaml`, `cache.py`, `logging_setup.py`.

Ключевая проверка 1.4 — `test_param_change_invalidates_own_stage_and_later_only`,
параметризована по всем 8 стадиям: смена параметра инвалидирует свою стадию и все
последующие, предыдущие остаются хитами.

**Решение 2.1.1 (принял агент, оставляю).** Цепочка ключей кэша линейна:
ключ стадии зависит от ключа предыдущей. Следствие — консервативная инвалидация
(смена `frames_fps` инвалидирует и ASR). Это ровно то, что требует 1.4; более
узкий граф зависимостей — возможное будущее уточнение, в скоуп не входит.

**Решение 2.1.2 (принял агент).** Идентичность входного файла по умолчанию —
`stat` (путь+размер+mtime); для 830 МБ есть режим `sample` (размер + 3 чанка по 1 МиБ)
и `content` (потоковый sha256). Чтение 830 МБ на каждом прогоне недопустимо.

**Решение 2.1.3 (принял агент).** `--no-cache` = «не читать кэш», запись артефактов
сохраняется — иначе стадиям некуда писать.

**Решение 2.1.4 (главная сессия).** В `pyproject.toml` добавлен
`[tool.setuptools.package-data] lecture_transcript = ["*.yaml"]` — без этого
`default_config.yaml` не попал бы в собранный wheel (в editable работало и ошибка
осталась бы незамеченной до сборки образа).

**Открытый стык (решается в конце волны).** core ввёл соглашение о вызове стадий:
пакет стадии экспортирует `run_stage(ctx)` с `cli.StageContext`. Агенты стадий 2–6
о нём не знали (запускались одновременно). Решено НЕ прерывать их: каждый делает
естественный API своего пакета, а после завершения волны агенту core отправляется
задание дописать в `cli.py` адаптеры под фактические сигнатуры. Так дешевле, чем
переделывать 5 пакетов под соглашение, придуманное параллельно с ними.

### 2.2 media-ingest (2.1–2.4) — готово

Реализованы `probe.py`, `audio.py`, `frames.py`, `_ffmpeg.py`. Тесты зелёные,
включая прогон на эталонной записи.

Факты, добытые агентом на эталонной записи: длительность **5482.13 с** (91:22),
извлечённый WAV — 5482.112 с, расхождение 18 мс; при 1 fps получено 5482 кадра
за 4 мин 20 с на CPU.

**Решение 2.2.1 (принял агент, оставляю) — кадры в JPEG q=2, не PNG.**
5500 кадров 1080p: PNG ≈ 10 ГБ против ≈ 1.5 ГБ JPEG. Дисперсия (D3) и phash (D4)
к JPEG q=2 устойчивы. **Следствие для slide-extraction:** кроп репрезентативного
кадра для OCR нельзя резать из JPEG-выборки — его надо переизвлечь точечно из mp4
в PNG (seek на одну секунду). Это условие передано агенту волны 2.

**Решение 2.2.2 (принял агент) — таймкоды кадров детерминированно `i / fps`.**
Фильтр `fps=N` строит равномерную сетку от нуля; строгая монотонность по
построению. Реальные pts потребовали бы второго прохода и могут повторяться при
дублировании кадров.

**Решение 2.2.3 (принял агент) — явно запрошенный недоступный hwaccel падает,
не откатывается молча.** На 91-минутной записи тихий откат превращает 2 минуты
в десятки, и это обязано быть заметно. Режим `auto` откатывается на CPU штатно.

**Решение 2.2.4 (главная сессия) — допуск длительности аудио 0.25 с.**
Оставлен как предложил агент: AAC priming/padding даёт 21–43 мс, наблюдаемое
расхождение 18 мс; допуск на порядок выше наблюдаемого и на порядок ниже
интервала выборки кадров.

**Решение 2.2.5 (главная сессия) — в контракт добавлена `MissingVideoTrackError`.**
Для «нет видеодорожки» бросалась базовая `PipelineError`, что не отличало этот
случай от любого другого сбоя. Симметрично `MissingAudioTrackError`. Агент
media-ingest переключён на неё. `MediaProcessingError` и `HwaccelUnavailableError`
оставлены локальными в пакете — они специфичны для стадии.

### 2.3 speech-transcription (5.1–5.8) — готово, 24 теста зелёные, 3 под маркером `models`

Реализованы `vad.py` (silero + энергетический бэкенд), `registry.py`, `base.py`
(`IntervalAsrBackend`), `gigaam_backend.py`, `whisper_backend.py`, `punctuation.py`,
`offline.py`, `pipeline.py`.

**Решение 2.3.1 (принял агент, ключевое) — выравнивание пунктуации по «ядру».**
D6 требует, чтобы таймкоды брались из ASR и не пересчитывались. Реализовано так:
поток `isalnum()`-символов исходных слов сравнивается с потоком пунктуированного
текста. Расхождение → пунктуация **не применяется** вовсе, выдаётся warning,
слова остаются исходными. Совпадение → каждое слово забирает свои символы плюс
примыкающие знаки. Состав слов и `start_s`/`end_s` сохраняются по построению.
Это сильнее, чем «постараться сохранить»: модель физически не может сдвинуть
таймкод, потому что таймкоды вообще не проходят через неё.

**Решение 2.3.2 (принял агент) — энергетический VAD как явный бэкенд, не фолбэк.**
`silero` / `energy` / `auto`; в `auto` при отсутствии silero — переход на energy
с предупреждением в лог и в `VadResult.warnings`, не молча. Это дало возможность
реально проверить 5.2 (абсолютность таймкодов после длинной паузы) здесь, без весов.

**Решение 2.3.3 (принял агент) — GigaAM не даёт по-словных таймкодов**,
слова распределяются внутри интервала VAD пропорционально длине. Точность привязки
ограничена длиной интервала VAD. Задокументировано в docstring; на качество
секционирования (6.1/6.2) влияет слабо, потому что границы секций — это слайды.

**Решение 2.3.4 (главная сессия) — тяжёлые runtime-зависимости НЕ дублируются
в `pyproject.toml` как extras.** Агент предложил `[project.optional-dependencies] asr`.
Отклонено: единственный источник правды по боевым версиям — `docker/requirements.txt`
(задача 1.2), где версии пинуются под CUDA-образ. Дублирование списка в двух местах
гарантированно разъедется. `pyproject.toml` остаётся описанием dev-окружения.

**Не проверено здесь:** 5.3, 5.4 (нужны веса GigaAM-v2 и Whisper large-v3),
реальный silero-vad, реальная модель пунктуации, прогон 5.8 в контейнере без сети
(заменён патчем `socket`/`getaddrinfo` + офлайн-переменными окружения).

### 2.4 transcript-assembly (6.1–6.6) — готово, 31 тест зелёный

Реализованы `merge.py`, `cleanup.py`, `paragraphs.py`, `render.py`, `pipeline.py`.

**Решение 2.4.1 (принял агент) — правило допуска на границах секций (6.2).**
Разрез между соседними секциями сдвигается к ближайшей границе фразы (промежуток
между словами ≥ 0.45 с либо конец предложения), но не более чем на
`section_boundary_tolerance_s` (дефолт 2.0 с, плейсхолдер под 7.6). Сдвиг не может
опустошить ни одну из двух соседних секций — это и есть защита от «съедания»
короткого слайда. Кандидата в окне нет → разрез остаётся на месте.

**Решение 2.4.2 (принял агент) — чистка филлеров только фильтрует список слов,
`Word` не пересоздаётся.** Тождество объектов проверяется тестом. Следствие:
таймкоды физически не могут сдвинуться при чистке. Порядок стадий зафиксирован:
merge (полнота 6.1) → cleanup → paragraphs → render — полнота проверяется ДО чистки,
иначе инвариант «ни одно слово не потеряно» противоречил бы удалению филлеров.

**Решение 2.4.3 (принял агент) — абзац не начинается от одной паузы.**
Разрыв ставится, только когда абзац «созрел» (≥45 с или ≥90 слов) И есть смысловая
граница; принудительный разрыв при 180 с / 320 слов. Это прямо отвечает требованию
6.4 «не одним блоком и не по каждой паузе».

**Решение 2.4.4 (принял агент) — ссылку на PNG рендерит `render.py`,
а картинки из `SlideOcr.markdown` вырезаются.** Иначе ссылка задваивалась бы:
её обязан класть и slide-ocr (4.5), и шаблон (6.5). Путь считается через
`os.path.relpath` относительно каталога транскрипта — транскрипт переносим.

**Проверено на синтетике, не на эталонной записи:** 6.2 (построен эквивалентный
момент переключения слайда) и 6.4 (синтетический десятиминутный монолог, 840 слов,
~70 пауз). Причина: стадий выше по пайплайну на момент работы агента ещё не было.
Реальная проверка — в сквозной задаче 7.1.

**Замечание в очередь на 7.6:** `phrase_gap_s` и параметры абзацев пока живут
дефолтами dataclass-политик модулей, а не в общем конфиге. При подборе значений
их надо поднять в `TranscriptAssemblyConfig`.

**Замечание в очередь на интеграцию:** в полном прогоне `pytest` падает по таймауту
`test_extract_frames_reference_1fps` (4 мин 20 с на эталонной записи). Нужен
`--timeout` либо исключение `slow` из дефолтного прогона.

### 2.5 slide-ocr (4.1–4.9) — готово, 66 тестов зелёные, 2 под маркером `models`

Реализованы `registry.py`, `routing.py`, `paddle_backend.py`, `pix2tex_backend.py`,
`hybrid_backend.py`, `vlm_backend.py`, `assemble.py`, `glossary.py`, `offline.py`.

> ### ⚠ Расхождение спеки с реальностью — решено самостоятельно
>
> **Слайда «Пример 2. √(x²−x) = −5» в эталонной записи НЕТ.** Это иллюстрация
> из `design.md` (D5), а не кадр записи. На неё ссылаются формулировки проверок
> в задачах **3.5** и **4.4**.
>
> Решение: считать её иллюстративной и проверять на реальном ближайшем аналоге —
> печатном слайде **«Пример 4. √(12−x) = x»** на t≈4260 с. Таймкод найден
> просмотром кадров эталона, задокументирован в самом тесте.
>
> Альтернатива — объявить 3.5 и 4.4 невыполнимыми — отвергнута: проверяемое
> свойство (репрезентативный кадр содержит дописанное решение; печатная формула
> распознаётся в LaTeX) от номера слайда не зависит.
>
> Второй найденный таймкод: **t≈425 с** — слайд «Как называются эти числа
> 1, 2, 3, 4, 5, 6, …?» из задачи 4.2, этот существует как заявлено.

**Решение 2.5.1 (принял агент) — отсечение оформления в глоссарии по геометрии,
без стоп-листов.** Надпись считается элементом оформления, если встречается
на ≥80% слайдов (минимум на 3) И центры её боксов расходятся ≤32 px. Это прямо
отвечает требованию design «никаких хардкодов под оформление конкретного шаблона»:
логотип платформы отсекается тем, что он всегда на одном месте, а не тем, что
он внесён в список.

**Решение 2.5.2 (принял агент) — правило `unreliable`.** Фрагмент неуверенный при
`confidence < 0.60`; слайд ненадёжен, если фрагменты есть и доля неуверенных ≥ 0.5.
Пустой слайд ненадёжным не считается — у него просто нет содержимого, и ссылка
на PNG всё равно есть.

**Решение 2.5.3 (принял агент) — формульному фрагменту ставится
`min(0.85, confidence исходной строки)`.** pix2tex своей уверенности не отдаёт;
потолок 0.85 отражает заявленную в D5 точность ~85%, а протаскивание confidence
исходной строки не даёт размытой строке стать «уверенной формулой».

**Не проверено здесь:** 4.2 и 4.4 на реальных весах (PaddleOCR, pix2tex не ставились),
реальное поведение `HybridBackend` на настоящих боксах, прогон 4.9 в контейнере
без сети (эмулирован патчем сокетов).

### 2.6 infra (1.1, 1.2) — артефакты готовы, проверка требует целевой машины

Созданы `docker/Dockerfile`, `compose.yaml`, `verify_env.sh`, четыре
`requirements*.txt`, `README.md`. Статические проверки — `tests/test_docker_artifacts.py`.

**Факт, добытый экспериментом (а не предположением):** apt-овый ffmpeg в
Ubuntu 22.04 **уже умеет nvdec**. Агент поднял `ubuntu:22.04` под amd64-эмуляцией,
поставил ffmpeg из apt: `-hwaccels` даёт `cuda`, `-decoders` — `h264_cuvid`.
Сборка ffmpeg из исходников не нужна. Флагов `--enable-nvdec` в строке configure
нет потому, что ffmpeg включает их автоматически при наличии заголовков ffnvcodec.

**Решение 2.6.1 (принял агент, неочевидное и важное) —
`NVIDIA_DRIVER_CAPABILITIES=compute,utility,video`.** По умолчанию
nvidia-container-toolkit прокидывает только `compute,utility`, и `libnvcuvid.so.1`
в контейнер не попадает. Симптом коварный: `nvidia-smi` работает, `-hwaccels`
показывает `cuda`, а декодирование падает. Прописано и в Dockerfile, и в compose;
в `verify_env.sh` есть отдельная проверка на `libnvcuvid` и сквозной тест
«закодировать libx264 → декодировать через `-hwaccel cuda -c:v h264_cuvid`».

**Решение 2.6.2 (принял агент) — весь стек версий продиктован `gigaam==0.1.0`,**
который объявляет `torch<=2.5.1`. Отсюда torch 2.5.1+cu124, torchvision 0.20.1,

### 4.2 Аудит transcript-assembly — 1×P0, 6×P1, 9×P2

Аудитор применил мутационное тестирование (снимал защиту и смотрел, упадут ли
тесты) и фаззинг на 14 000 входов. Инвариант полноты 6.1 сломать не удалось —
он держится. Кросс-процессный тест детерминированности настоящий.

> **P0: `merge.py` сортирует секции по индексу слова, а не по времени.**
> На валидном входе получается «Слайд 1 → Слайд 3 → Слайд 2» с обратными
> интервалами в заголовках. Воспроизведено.

> **P1, самое важное по существу задачи: чистка филлеров ломает содержание
> математической лекции.**
>
> - «два плюс два плюс два» → «два плюс два» (дедуп n-грамм рушит арифметику)
> - «ноль ноль один» → «ноль один»
> - «Пусть n n стремится» → «Пусть n стремится»
> - «Как бы вы доказали это» → «вы доказали это» (фразовый филлер режется безусловно)
> - «Это самое важное свойство» → «важное свойство»
> - «Он он знает» → «он знает» (теряется заглавная — удаляется ранняя копия)
> - «длина равна пяти м» → «...пяти» («м» в списке филлеров съедает единицу измерения)
>
> Это прямое нарушение design → Risks: «правила консервативные, чистятся только
> явные заполнители; сомнительное остаётся». Для лекции по математике цена ошибки
> здесь максимальная: испорченная формула в конспекте не отличима от верной.

Прочие P1: первый абзац секции никогда не получает таймкод (`position > 0`),
нарушая требование «Таймкоды для сверки»; тест `test_tolerance_does_not_swallow_short_slide`
не может упасть — аудитор снял всю защиту 6.2, тесты остались зелёными.

Запущен отдельный агент правок с явным требованием сделать чистку строго
консервативнее: числительные, однобуквенные математические обозначения и единицы
измерения выводятся из-под дедупа и из списка филлеров.

### 4.3 Аудит slide-ocr — 4×P0, 10×P1, 6×P2

Существующие 66 тестов не ловят ни одну находку — это само по себе диагноз
по качеству тестов стадии.

P0: `parse_paddle_output` падает `ValueError` на выдаче PaddleOCR 3.x (проверка
`or` над `numpy.ndarray`); `sort_fragments` переворачивает строку при джиттере
bbox в 2 px; отсечение оформления в глоссарии использует `all(...)` вместо доли,
поэтому один выбившийся bbox пропускает логотип платформы в глоссарий;
дефолт `backend: paddle+pix2tex` не существует в реестре (`hybrid|paddle|vlm`).

> **P1 №5 — содержательно самая важная находка по всей стадии.**
> Строка с низкой уверенностью (типично — рукописная пометка маркером) уходит
> в pix2tex и **заменяется галлюцинированным LaTeX**.
>
> Это ровно то, что design D5 запрещает буквальным текстом: «изображение слайда
> под рукой полезнее, чем галлюцинация модели на месте рукописной записи».
> Роутинг «низкая уверенность → формульный распознаватель» задумывался для
> печатных формул, которые PaddleOCR плохо читает, и был по недосмотру
> распространён на рукописное.

Парная находка 3/7: эвристика отсечения оформления одновременно пропускает
логотип платформы и отсекает настоящий термин лекции (заголовок темы в шапке
каждого слайда). Чинить надо вместе — правка одной усугубляет другую.

**Решение 4.3.1 (главная сессия).** Дефолт `slide_ocr.backend` в
`default_config.yaml` переведён с несуществующего `paddle+pix2tex` на `hybrid`.
Сделано в главной сессии, а не агентом правок: файл конфига — общий,
и в этот момент в него писал агент slide-extraction (порог 3.7).

### 4.5 Правки transcript-assembly — закрыто 7 находок P0/P1 + 3×P2, тестов 31 → 51

**Решение 4.5.1 (принял агент правок) — новое правило чистки филлеров.**
Удаление разрешено только при отсутствии сомнения:

- числительные, однобуквенные токены и слова формул выведены из-под дедупа
  целиком — в математической лекции их повтор нормален;
- список фразовых филлеров разделён надвое: однозначные удаляются всегда,
  омонимичные («как бы», «это самое», «так сказать») — только там, где оборот
  не открывает предложение И обособлен паузой/запятой **с обеих** сторон;
- при повторе с заглавной буквы удаляется поздняя копия, а не ранняя.

Каждое правило только СУЖАЕТ удаление — ни один ранее сохранявшийся фрагмент
теперь не режется. Осознанная цена: часть филлеров остаётся («предел как бы
равен» не чистится), и это зафиксировано тестом как ожидаемое поведение.
Обоснование — design → Risks: «сомнительное остаётся».

**Решение 4.5.2 (принял агент) — P0 с порядком секций починен конструктивно.**

переставить их между собой: инвариант полноты 6.1 защищён не проверкой, а
структурой. Фаззер аудитора: нарушений порядка было 2 → стало 0; на невалидных

**Отклонено агентом с обоснованием (согласен, не настаиваю):** экранирование
Markdown в тексте речи (меняет текст, риск выше пользы), `Path.resolve()`
в relpath (ходит в ФС и разыменовывает симлинки — против побайтовой
детерминированности 6.6), `raise` при пересекающихся интервалах слайдов
(меняет контракт публичной функции; такой вход и так отбрасывается валидатором).

### Решения, принятые агентом (оставляю все)

**5.1 — разброс считается робастно (MAD×1.4826), а не как обычная σ.**
Четыре кадра «провала демонстрации» из 300 поднимают σ слайда до ~20 и рушат
маску. Это ровно тот случай, где обычная дисперсия из D3 не работает на реальных
данных, а идея D3 — работает.

**5.2 — гистерезис `min_absence_s = 20 с` и порядок операций.** Все 44 артефакта
переключения ≤13 с, единственное настоящее выключение — 60 с. Сначала гасятся
всплески в 1–2 кадра, потом заполняются короткие провалы; обратный порядок
«лечил» настоящее выключение. Результат на эталоне: ровно 2 интервала раскладки
вместо 45 сырых провалов.

**5.3 — область интервала = объединение областей его окон** (`stable_region_iou=0.75`).
Шаблон слайдов оставляет светлым разное поле, и по одному окну получалось бы
пересечение — кроп для OCR терял бы содержимое справа.

**5.4 — PNG-кроп переизвлекается точечно из mp4** (`ffmpeg -ss T -frames:v 1 -vf crop`),
с откатом на кроп из JPEG-выборки и предупреждением в лог. Это закрывает
следствие решения 2.2.1 (кадры выборки — JPEG q=2, для OCR формул не годятся).

### 5.1 Правки slide-ocr — закрыты все P0 и P1, тестов 66 → 98

**Решение 5.1.1 (принял агент правок) — правило «рукописное против печатной
формулы», трёхчастное.** Это ответ на самую важную находку аудита:

- низкая уверенность уводит строку в pix2tex **только при наличии
  математического признака** — она снимает порог доли слов, но не заменяет
  собой наличие математики;
- строка с уверенностью < 0.35 и вовсе без математики опознаётся как рукописная
  и **выбрасывается гибридом целиком** — ни текстом, ни формулой; доступ к ней
  даёт ссылка на PNG. Это буквальная реализация D5, категория [3];
- если строка ушла в pix2tex только по уверенности, результат помечается
  `low_confidence` («сверьтесь с изображением»), а не выдаёт себя за надёжный.

Страховка от перегиба тоже покрыта тестом: плохо прочитанная **печатная**
формула в pix2tex всё ещё уходит.

**Решение 5.1.2 (принял агент) — правило отсечения оформления стало
трёхчастным и наконец различает два похожих случая.** Частота ≥0.8 слайдов
И ≥0.8 боксов в допуске от медианы (вместо `all`) И строка не состоит целиком
из слов, встречающихся на слайдах вне неё.

Третий пункт — суть находки: плашка платформы («Онлайн-школа») больше нигде
в лекции не звучит, а заголовок темы («Квадратные уравнения») состоит из слов
словаря самой лекции. Геометрии для их различения не хватало.

**Решение 5.1.3 (принял агент) — экранирование Markdown только для `kind="text"`,**
формулы не трогаются; путь к PNG кодируется процентами, а не оборачивается
в `<...>` — так остаётся рабочим регексп `_IMAGE_LINK` в transcript_assembly,
который вырезает картинки из врезки (решение 2.4.4).

**Решение 5.1.4 (принял агент) — `check_availability()` проверяет наличие
локальных весов без сети** (`~/.paddleocr`, `~/.paddlex`, чекпойнты пакета
pix2tex, HF-кэш) и меряет **свободную** VRAM через `mem_get_info`, а не
`total_memory`. Иначе прогон падал бы в середине при `HF_HUB_OFFLINE=1`
или ловил OOM на середине стадии.

**Проверка контракта стала содержательной.** Вместо `isinstance(..., OcrBackend)`,
которое проходило для класса с любыми сигнатурами, — сверка сигнатур через

### 5.2 Доработка core — стыковка стадий, дефолты, стадия `frames` подключена

### 5.3 Правки speech-transcription — закрыты все P0/P1, тестов 24 → 53

**Решение 5.3.1 (принял агент) — нарезка длинных интервалов VAD под лимит модели.**
`GigaAmBackend.max_chunk_s = 20.0` с запасом к порогу 25 с из `gigaam 0.1.0`.

### 5.5 Разделение стадий `audio` и `frames`

`media_ingest` разделён на два независимых входа: `run_audio_stage` (только
`audio.wav`) и `run_frames_stage` (только кадры). Независимость ячеек закрыта
тестами со счётчиком запусков ffmpeg: смена `audio_track` не переизвлекает кадры,
смена `frames_fps` не пересчитывает WAV.

> ### ⚠ Следствие, меняющее модель кэша: линейная цепочка перестала описывать
> реальность
>
> `cache.chain(...)` строит ключ каждой стадии поверх ключа предыдущей. Пока
> стадии шли строго в ряд, это работало. Теперь `audio` и `frames` — **две
> независимые корневые стадии**: ни одна не потребляет результат другой, обе
> зависят только от исходного файла. Если оставить их соседями в линейной цепочке,
> смена `audio_track` снова инвалидирует 5500 кадров через `previous_key` — то есть
> мы вернёмся ровно к проблеме, из-за которой стадии и разделили.
>
> Дальше развилка только усложняется: `slides` зависит только от `frames`,
> `vad` — только от `audio`, а `merge` — от обеих ветвей. Это в точности структура
> из design D2, которую линейный список стадий не выражает.
>
> Поручено core: заменить позицию в списке на явный список стадий-предшественниц
> (для `audio` и `frames` — пустой). Решение 2.1.1 («линейная цепочка, сознательно
> консервативная инвалидация») тем самым отменяется: оно было верным, пока граф
> был цепочкой, и перестало быть верным, когда граф стал деревом.

**Решение 5.5.1 (принял агент media-ingest) — `audio` идёт ПЕРЕД `frames`.**
Тогда «видео без аудиодорожки» падает сразу, а не после четырёх минут
извлечения 5500 кадров.

### 6.3 Итерация 2 аудита speech-transcription

Подтверждено воспроизведением: **10 из 11** закрытых находок. Нарезка кусков

> ### ⚠ P0 — пунктуация не работала бы вообще, ни на одном куске
>
> `SbertPuncCaseRu._load` зовёт `SbertPuncCase.from_pretrained`, а у пакета
> с пинованного коммита такого метода нет: это `nn.Module` с `__init__()` без
> аргументов. Каждый кусок падал бы `AttributeError`, текст уходил бы без
> пунктуации — и из-за громкого отказа это хотя бы было бы видно, но только
> в одном из путей (см. ниже).
>
> Аудитор воспроизвёл на **настоящем коде пакета**, скачанном с HF, заменив
> torch/transformers заглушками. Итерация 1 этого не поймала, потому что фейковый
> пунктуатор в тестах был удобным и имел `from_pretrained`. Урок записываю
> явно: фейк должен повторять реальную сигнатуру зависимости, иначе тест
> проверяет наше представление о библиотеке, а не саму библиотеку.

> ### P1 — громкий отказ и очистка памяти не доходили до боевого пути
>
> Правки итерации 1 положили предупреждение об отказе пунктуации и очистку
> кэша WAV в `transcribe_speech`. Но CLI этот метод не зовёт — адаптеры в
> `cli.py` вызывают функции пакета напрямую. В боевом прогоне отказ оставался
> тихим, а 351 МБ сэмплов висели в памяти после ASR. Регрессия от кэша WAV.
>
> **Решение 6.3.1 (главная сессия).** Не править адаптеры в `cli.py`, а объявить
> точки входа `run_vad_stage` / `run_asr_stage` / `run_punctuation_stage`
> в самом пакете. Оркестратор специально сделан так, что точка входа пакета
> побеждает адаптер (решение 5.10.1) — это первый случай, когда этот механизм
> используется по назначению. Форма нагрузок берётся из текущих адаптеров,
> иначе сломается `merge`. Проверка — сквозь CLI, а не функцией пакета.

> ### P1 — GigaAM не может получить глоссарий, и это расхождение с design
>
> Design D2 и формулировка задачи 5.3 предполагают передачу глоссария в GigaAM
> как hotwords. **`gigaam 0.1.0` hotwords не принимает** — подтверждено двумя
> независимыми аудитами. `models`-тест 5.3 был бы на целевой машине всегда красным.
>
> **Решение 6.3.2 (главная сессия).** GigaAM честно объявляет
> `supports_glossary = False`; для него срабатывает деградация 5.5 (прогон без
> глоссария с предупреждением); тест 5.3 для GigaAM переписан на ожидание этой
> деградации. Для Whisper глоссарий через `initial_prompt` остаётся.
>
> **Сознательно НЕ сделано** — постобработка «подогнать написание распознанных
> слов под глоссарий» (нечёткое сопоставление с сохранением таймкодов). Это
> достигло бы цели D2 другим механизмом, но это новый механизм сверх спеки.
> **Выносится пользователю как предложение, см. итоговый раздел.**
>
> Следствие: задача 5.3 в формулировке «термины распознаны в написании глоссария»
> для бэкенда по умолчанию (GigaAM) **невыполнима на пинованной версии модели**.
> Это вопрос к design, а не к реализации.

Прочие новые находки — 6×P2: разрез не всегда попадает в паузу (14 из 201
на лекции), частичный отказ пунктуации не громкий (поднят до обязательного),
устаревший кэш WAV при том же размере и mtime, остаточная потеря знаков
при выравнивании.

### 6.5 Правки transcript-assembly, итерация 2 — тестов 51 → 68, полный прогон 467 passed

**Слово нулевой длительности** теперь относится к слайду по точке `start_s`:
точка ровно на переключении уходит к следующему слайду, на конце последнего —
к нему. Дифференциальный фаззинг (40 тыс. входов): 0 дублей секций, 0 нарушений
порядка, 0 слов внутри слайда в «Речи вне слайдов».

**Регрессии чистки закрыты:** «Мы мы мы» → «Мы». Если пунктуация копий различается
(«Это, это важно.»), повтор теперь **остаётся**: любое удаление теряет либо
заглавную, либо запятую, а создавать новый `Word` запрещает решение 2.4.2
(таймкоды не должны проходить через чистку). Консервативный выбор, согласуется
с design → Risks.

**Решение 6.5.1 (принял агент) — сужение правила однобуквенных токенов.**
Из-под защиты сняты «в, и, с, к, у, я» — снова чистятся «в в этом случае»,
«я думаю я думаю». Но «а» и «о» оставлены под защитой: так же произносятся
точки A и O. Заглавная пара («точка В В») тоже защищена. В математические токены
добавлены названия букв («бэ», «вэ», «цэ»…), иначе «отрезок бэ бэ один» резался бы.
Все математические контрпримеры итерации 1 остались зелёными. Это содержательнее
моей подсказки «латиница против кириллицы» — агент учёл, как буквы звучат вслух.

**Отклонено с обоснованием (согласен):** расширение интервала секции до интервала
слов (заголовки соседних секций начали бы перекрываться); `section.paragraphs`
в рендере (контракт хранит только строки без времени, а `contracts.py` менять нельзя).

**Спор о `Path.resolve()` разрешён проверкой, а не аргументами.** Прежнее
обоснование агента было неверным — но и аудитор ошибся: `resolve()` зависимость
от cwd не убирает. Агент проверил из `/tmp` и `/usr` — оба способа дают одинаковые
пути. Относительный путь по определению отсчитывается от cwd; при смеси
абсолютного и относительного пути любой правильный ответ зависит от cwd.
Через CLI сценарий недостижим. Отклонено, теперь с верным обоснованием.

**Агент сам отозвал своё утверждение из итерации 1** «каждое правило только
сужает удаление» — аудитор показал регрессии, утверждение было неверным.

> **Решение 6.5.2 (главная сессия) — последний случай удаления содержания
> закрывается сейчас, а не откладывается.** Открытым оставался P2 №4:
> «как бы вы доказали» → «вы доказали» в тексте **без пунктуации** при паузе ≥0,3 с.
> Аудитор дал P2, но по сути это удаление содержания — ровно то, что design → Risks
> запрещает. Без пунктуации единственный сигнал «вставка» — пауза, а пауза сама
> по себе омонимию не разрешает. Поручено самое консервативное правило:
> без пунктуации вокруг омонимичный оборот не удаляется никогда.
> Однозначные филлеры это не затрагивает.

> **Дополнение к решению 6.2.** Повторный аудит slide-ocr запущен со второй
> попытки — переформулированным заданием, без переопределения модели. Итерация 2

### 6.6 transcript-assembly — последний случай удаления содержания закрыт

Омонимичный оборот («как бы», «так сказать», «скажем так», «это самое») теперь
удаляется только при трёх условиях одновременно: не открывает предложение,
обособлен запятой или тире **с обеих сторон**, и с обеих сторон пауза ≥0,3 с.

не удаляется никогда. Однозначные филлеры и самоповторы правило не затрагивает
(«ээ ну вот смотрите мы мы рассмотрим э предел» → «смотрите мы рассмотрим предел»
и до, и после правки).

Два старых теста изменены сознательно: они закрепляли поведение, которое теперь
запрещено («как бы предел функции» без пунктуации ожидался удалённым).

Полный прогон: **500 passed, 0 failed**. По transcript-assembly известных открытых
замечаний не осталось; отклонённые P2 имеют обоснования, проверенные по фактам.

## 8. Интеграция

Все шесть зон закрыты. Запущены параллельно две задачи, разблокированные
окончанием правок slide-ocr:

1. **Модуль `warmup`** (агент core) — прогрев весов всех выбранных бэкендов их же

2. **Сухой сквозной прогон на всей эталонной записи** (новый агент). Настоящий

   только OCR/ASR/пунктуация детерминированными фейками. Проверяет всё, кроме

   секций, число и длительности секций вне слайдов (риск 5.12), детерминированность,
   тайминги стадий на CPU, попадание в кэш при повторе, формат для задачи 7.5.

**Решение 8.1 (главная сессия) — скрипт сухого прогона кладётся в репозиторий
(`tools/dry_run.py`), а не только в scratchpad.** Это единственный способ проверить
интеграцию без GPU и весов; он пригодится после любой правки стадий, пока целевая
машина недоступна.

**Задачи 7.x сухой прогон НЕ закрывает** — их формулировки требуют настоящего
распознавания, VRAM и времени на GPU. Он закрывает риск, что на целевой машине
пайплайн упадёт на стыке стадий, а не на моделях.

  проверка из формулировки (число кадров и монотонность меток) выполнена на CPU.
- **3.3** — «число переходов совпадает с ручным подсчётом»: ручной подсчёт

- **3.7** — порог 43 подобран и подтверждён на эталоне, но на этой записи все

### 8.2 Модуль `warmup` готов — полный прогон 552 passed

`python -m lecture_transcript.warmup` снимает офлайн-режим только на время прогрева
(запреты телеметрии остаются), загружает модели выбранных бэкендов по одной
с `unload()` после каждой, печатает сводку OK/FAIL с причиной, код 1 при любом
отказе. `compose.yaml` вызывает модуль без аргументов — совпадает с реализацией,
закреплено тестом. Режимы: по умолчанию бэкенды из конфига, `--all`, `--with-vlm`.

**Решение 8.2.1 (принял агент, тонкое и верное) — список офлайн-переменных
читается разбором исходников, без импорта модулей.** `huggingface_hub` запоминает
`HF_HUB_OFFLINE` в момент собственного импорта; если импортировать модуль стадии
раньше, чем снят офлайн, снимать его потом бесполезно — прогрев бы молча ничего
не скачал.

**Решение 8.2.2 (принял агент) — загрузка через минимальные фиктивные вызовы.**
Пакеты не дают способа «загрузить модель без распознавания», а лезть в их зоны
агент не стал: OCR — `recognize()` пустого PNG 64×32 (у `hybrid` — обе части
отдельно, иначе на пустой картинке pix2tex не загрузится), ASR — секунда тишины,
silero — `detect_speech()` на тишине, пунктуатор — две слова.

**Оговорка, записанная в долг, а не в правку.** Финальная проверка «после прогрева
бэкенд доступен в офлайне» слабее, чем задумано: у pix2tex, пунктуатора, silero
и gigaam `check_availability()` смотрит только на установленные пакеты. Для MVP
это не блокер — успешная фиктивная загрузка при прогреве сама скачивает веса,
и сводка честно покажет FAIL, если загрузка не прошла.

### 8.5 Фейковый OCR сухого прогона выводится из содержимого PNG

Текст фрагментов теперь зависит от кропа, а не от номера слайда: светлая карточка
слайда уменьшается до 32×18 в оттенках серого, яркость квантуется до 6 уровней,
от этого берётся хэш. `slide_019` и `slide_020` получают одинаковый текст,
соседние разные слайды — разный; при сдвиге окна на 2 px хэш сохраняется
в 208 из 212 вариантов. На всей записи ожидается 2 слитые группы (53 → 51 секция).

Где сухой прогон слияние **не проверит** (фейк чувствительнее настоящего OCR):
слайд с дописанным рукописным ответом (20/21), дорисованный эскиз (27/28),
«Итоги лекции» 46–49 со сменой масштаба окна.

> **Поправка к решению 8.3.2, найденная благодаря этому отчёту.** Я задал правило
> «при слиянии PNG и врезка — от последнего слайда группы». Но настоящий гибридный
> OCR выбрасывает рукописное (D5), поэтому два соседних состояния слайда с одной
> печатной заготовкой и **разным рукописным решением** дадут одинаковый текст
> и сольются — а ранний PNG с первым решением исчезнет из транскрипта. Это ровно
> та потеря решения, от которой защищают D4 и D5. На эталоне реальный случай —
> 20/21: на 21 дописан «Ответ: −0,2».
>
> Исправленное правило: слитая секция — один заголовок, одна врезка OCR, но
> **ссылки на все различающиеся PNG группы**; побайтово одинаковые картинки
> показываются один раз. Лишние заголовки и повторы врезок уходят, содержание
> не теряется. Поправка отправлена агенту transcript-assembly во время его работы.

### 8.6 transcript-assembly — формат транскрипта под конспект

Полный прогон: **575 passed**. Мутационная проверка слияния и присоединения —
11 мутаций, все убиты.

**На эталонной записи** (кэш стадий до `merge`): секций **98 → 54**,
«Речь вне слайдов» **45 → 1** (осталось вступление 60 с), тема в заголовке у 44

Пример заголовка: `## Слайд 1 — Пример 1. Решите уравнение — 0:01:00–0:04:08`.

**Решение 8.6.1 (принял агент) — группировка одинаковых слайдов на уровне рендера,
а не структуры.** `TranscriptSection` вмещает один `slide`, контракт менять нельзя,
поэтому в `Transcript.sections` каждый слайд остаётся со своим PNG и интервалом,
а рендер выводит группу одним заголовком `## Слайды 19–20 — …`, одной врезкой
и ссылками на все различающиеся по содержимому PNG. Поправка из 8.5 соблюдена.

для MVP это неважно, потребитель один, и это `transcript.md`.

**Решение 8.6.2 (принял агент) — порог присоединения 15 с, строгое «меньше».**
Провалы демонстрации длятся 3–13 с, самая короткая настоящая речь без слайда —
вступление 26 с. 0 выключает правило.

**Рендер снимает лишнюю цитату-пометку slide-ocr** в начале `markdown` —
пометка ненадёжности выходит ровно одна независимо от версии slide-ocr.
Параллельно slide-ocr уже убрал её у себя (8.4); защита с двух сторон безвредна.

> **Найдено попутно — P1 против D8.** Кэш стадии не учитывает версию кода.
> Агент поменял шаблон, прогнал на старом кэше и получил прежний `transcript.md`
> без правок, пока вручную не удалил `cache/merge`. D8 прямо обещает «смена
> шаблона вывода — инвалидирует только сборку», и кэш существует ради быстрых
> итераций по формату. Молча отдать устаревший результат — худший вид дефекта
> кэша. Поручено core: отпечаток исходников пакета стадии в ключе, инвалидация
> стадии и потомков, но не предков.

Остаток сухого прогона: слияние одинаковых соседних слайдов на эталоне проверено
только тестами — прошлый фейк OCR давал слайдам разный текст. Повторный сухой
прогон с фейком по содержимому PNG — после правки кэша, иначе он сам наткнётся
на ту же проблему.

## 10. Что требует решения пользователя

Всё остальное в этом файле решено автономно и может остаться как есть. Эти пункты
меняют поведение относительно спеки или design — их стоит прочитать.

1. **Короткая «Речь вне слайдов» присоединяется к соседнему слайду (8.3.2, 8.6.2).**
   Спека transcript-assembly требует отдельных секций для речи вне слайдов.
   На эталонной платформе каждая смена слайда даёт провал демонстрации 3–13 с,
   и без присоединения транскрипт распадается на 45 обрывков по несколько секунд.
   Секции короче 15 с присоединяются, длинные остаются. Выключается
   `transcript_assembly.short_offslide_section_s: 0`. Если согласны — стоит внести
   в спеку через `/opsx:update`.

2. **GigaAM не получает глоссарий (6.3.2).** Design D2 строится на подаче глоссария
   слайдов в ASR как hotwords, а `gigaam 0.1.0` hotwords не принимает. Сейчас
   GigaAM работает без глоссария с предупреждением; Whisper получает его через
   `initial_prompt`. Задача 5.3 для бэкенда по умолчанию на этой версии модели
   невыполнима. Варианты: (а) принять и поправить D2/5.3; (б) постобработка —
   подгонять написание распознанных слов под глоссарий нечётким сопоставлением
   с сохранением таймкодов; это новый механизм, не делал без апрува;
   (в) Whisper по умолчанию для лекций с плотной терминологией.

3. **Порог hamming 43 проверен только на платформе, где смена слайда идёт
   с провалом демонстрации (6.4).** На эталоне ни одна смена слайда порогом
   не решается — все режутся по провалу. На другой платформе вебинаров порог
   придётся перепроверить.

4. **Соседние одинаковые слайды группируются рендером, а не в структуре данных
   (8.6.1).** Контракт `TranscriptSection` вмещает один слайд; менять `contracts.py`
   ради этого не стал. Для `transcript.md` разницы нет.

### Замечания к формату транскрипта (7.5)

Транскрипт читается как исходник конспекта: речь чистая, с пунктуацией,
разбита на абзацы, секции идут по слайдам, промежуточные таймкоды на месте.
Проблемы, по убыванию влияния:

1. **Заголовок секции — логотип.** 53 из 57 секций названы «СИНЕРГИЯ»:
   `slide_title` берёт первую текстовую строку OCR и про оформление не знает.
   Логотип при этом и первый термин глоссария, проверка 4.7 не проходит.
   Причина — третий критерий `find_decoration_lines`: слово «Синергия»
   один раз встречается в теле слайда со списком литературы («Университет
   «Синергия»»), и плашка сходит за заголовок темы. Гипотеза из `TECH_DEBT.md`
   подтвердилась на реальных данных.
2. **Смешанная строка «Ряд A: y = 2x + 1; …» целиком уходит в pix2tex.**
   Paddle прочитал её как текст с уверенностью 0.89, а pix2tex превратил
   «Ряд А» в `{\mathrm{p}}_{R R}{\mathrm{A}}`. Гипотеза из `TECH_DEBT.md`
   подтвердилась.
3. **Мусорные формулы pix2tex на рукописном и графиках.** Пометки `(?)`
   у них нет (`DEFAULT_FORMULA_CONFIDENCE`), поэтому слайд с графиком и
   рукописными `D(f)`, `E(f)` (слайд 18) не помечается ненадёжным, хотя
   половина его врезки — мусор.
4. **Подписи осей графиков** идут отдельными строками («4.0», «3,5», …) и
   раздувают врезку. Для конспекта бесполезны.
5. **Фраза рвётся на границе секций**: «…сначала мы немножко повторим, потом» |
   «Мы, ребята, пойдём на свойства функции» (слайды 1→2), «Давайте я.» |
   «Напомню, ребята…» (3→4). Допуск на границах (6.2, 7.6) на этой записи
   не подобран.
6. Первое окно раскладки (0–300 с) — область демонстрации неуверенная, взята
   опорная. На результат не повлияло.

Решения по пп. 1–5 меняют эвристики и ждут апрува пользователя.
